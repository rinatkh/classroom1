# Classroom 1 — терминал, GitHub workflow и первый Go-проект

Этот репозиторий используется на первом занятии для live coding.

## Цели урока

После урока ученик должен уметь:

1. Открывать терминал и понимать, куда вводить команды.
2. Перемещаться по папкам через `pwd`, `ls`, `cd`, `mkdir`, `touch`, `cat`.
3. Понимать базовый workflow GitHub: fork → clone → branch → commit → push → pull request.
4. Запускать первый Go-проект через `go run`.
5. Запускать тесты через `go test ./...`.
6. Понимать минимальную структуру Go-проекта: `go.mod`, `cmd`, `internal`, package, import.

## Как запустить проект

```bash
go run ./cmd/app
```

## Как запустить тесты

```bash
go test ./...
```

## Как запустить все проверки

```bash
make check
```

## План live coding

1. Открыть терминал.
2. Проверить текущую папку через `pwd`.
3. Посмотреть файлы через `ls`.
4. Открыть проект в VS Code.
5. Запустить `go run ./cmd/app`.
6. Изменить текст приветствия в `internal/greeter/greeter.go`.
7. Запустить тесты и увидеть ошибку.
8. Исправить тест или код.
9. Создать ветку, commit, push.
10. Открыть Pull Request.

## Мини-команды

```bash
pwd                 # показать текущую папку
ls                  # показать файлы
cd folder           # перейти в папку
cd ..               # выйти на уровень выше
mkdir projects      # создать папку
cat README.md       # показать содержимое файла
clear               # очистить терминал
```

## Проверки как на работе

В проект добавлены проверки, которые удобно показывать на Pull Request / Merge Request:

```bash
make fmt-check  # проверяет gofmt и табуляцию Go-кода
make vet        # запускает стандартные проверки Go
make test-ci    # запускает тесты с race detector и coverage
make lint       # запускает строгий golangci-lint
make ci         # полный набор проверок, как в GitHub Actions
```

`make lint` теперь не пропускает проверку молча. Если `golangci-lint` не установлен, Makefile
скачает закреплённую версию из архива GitHub Releases в локальную папку `bin/`. Это не
использует `go install`, поэтому установка не зависит от корпоративного `GOPROXY`/Nexus.

Основные строгие правила:

- Go-код должен проходить `gofmt` и `gofumpt`.
- Отступы Go-кода — табы, это контролируется форматтерами.
- Максимальная длина строки — 100 символов.
- Максимальная длина функции — 40 строк или 25 statements.
- Цикломатическая сложность функции — до 10.
- Включены проверки `govet`, `staticcheck`, `errcheck`, `gocritic`, `revive`, `gosec` и другие.

## GitHub CI

Файл `.github/workflows/ci.yml` запускается на каждый `pull_request` и `push` в `main`.
CI делает то же самое, что программист делает локально:

```bash
make ci
```

В Pull Request будет видно, какая проверка упала: форматирование, тесты, `go vet`, линтер,
race detector, coverage или сборка бинарника.

Для `push` в `main` workflow дополнительно собирает `tar.gz`-артефакт приложения и
прикладывает его к запуску Actions. Это имитирует простую CD-часть без реального деплоя.
